## Changes

- **Files the model cannot read now reach the agent** — Documents, archives, spreadsheets, presentations and any other file type without native model support are saved unchanged to a private local inbox, and the agent receives their absolute path together with the caption instead of a "file type not supported" reply.
- **PDFs and office documents fall back too** — When the model has no PDF input and `DOC_EXTRACTOR_URL` is unset or returns nothing, text documents are saved to the inbox and their path is passed to the agent rather than the message failing.
- **Inbox location and retention** — New `FILE_INBOX_DIR` setting chooses where saved files go (`<bot home>/inbox` by default) and `FILE_INBOX_RETENTION_DAYS` keeps uploads for 7 days by default, `0` keeps them forever. Each upload gets its own directory, files keep their original name with owner-only permissions, and album uploads are handled one by one.
- **Clear reply when saving fails** — If the file cannot be written (too large for the Telegram download limit, or a filesystem error), the bot says so plainly instead of silently dropping the message, and the rest of an album is still delivered.

Robustness in this candidate:

- Long non-ASCII filenames are limited by UTF-8 bytes, so they save on Linux filesystems instead of failing with a name-length error.
- Windows device names such as `CON` or `NUL` get a `_` prefix, so the upload still saves on Windows.
- Retention prunes only the directories the bot created, so pointing `FILE_INBOX_DIR` at a shared folder no longer risks deleting unrelated files.

This release candidate covers [issue #250](https://github.com/grinev/opencode-telegram-bot/issues/250).
